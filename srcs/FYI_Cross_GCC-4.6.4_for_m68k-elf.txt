2. ホスト側での作成作業
    2.1 事前作業
        ・インストール先を決めましょう
            自分専用のホストであれば/usr/local以下にm68k-elfを置く(というのが一番スッキリすると思うのですけれども、どうでしょう？)
            共用のホストであれば~/bin以下などにm68k-elfを置く
            以後、その場所を{INSTALL_PATH}と表します
        ・{INSTALL_PATH}にPATHを通しておきましょう(下記の2.2を実行した後でも可です)
    2.2 binutils-2.25のbuild
        コレは素直に：
            configure --prefix={INSTALL_PATH} --target=m68k-elf
            make
            sudo make install
        でOKです
        ※後述するオプションも一読してみてください
    2.3 gcc-4.6.4のbuild
        メインイベントです。./configureにpatchを当ててから：
            configure --prefix={INSTALL_PATH} --target=m68k-elf \
                --disable-libquadmath --disable-ssp
            make
            sudo make install
        でOK(たぶん)
        ※必要に応じて、--enable-languages=c,ltoなど添えるのもオツなモノ。
        ※libquadmathとsspを使いたい人は、ガンバって。
    2.4 newlib-cygwinのbuild
        2.3までで作成したツールの試運転をしてみましょう
	    (newlib-cygwinはgit cloneなさってね)
        ※なお、間違いなく失敗すると思います(CPU時間のムダ遣いなので省略可)
            cd newlib-cygwin
            configure --prefix={INSTALL_PATH} --target=m68k-elf
            make
        しかし、"internal compiler error: in gen_rtx_SUBREG"などと怒られて止まるでしょう
        ガンバって修正してみるのも一興ですけれども。。。
    2.5 古いnewlibのbuild
        newlib-2.5.1です。コレはもう、何のヒネりも無く：
            TOOL=binutils CFLAGS='-std=c99' \
            configure --prefix={INSTALL_PATH} --target=m68k-elf
            make
            make check
            sudo make install
        です
        ※イマドキのgccでbuildする場合、CFLAGSを追加しないとコケるかも。
        ※m68k-elfのみ？：setjmp()とlongjmp()が正しく参照できないようです。
                          必要に応じて自製するか、newlibを修正しましょう。
                          (必要とする人なら、動作を理解できるハズです)
    2.6 オプション：binutilsの再build、あるいはbinutilsのアップデート
        newlibが出来たので、--with-newlibを指定する辻褄が合います。そこで：
            configure --prefix={INSTALL_PATH} --target=m68k-elf --with-newlib
            make
            sudo make install
        とします。バージョンを上げるのもアリですわね。ワタクシはbinutils-2.43にしました。
        ※ただし、binutils-2.43のbuildは、makeinfoやlibbfdがないとコケます。
        　binutilsのopcodes/dis*などで使っているらしい、です
        　お使いの環境に合わせてインストールして下さい(apt-getやdpkgなどがラクですわね)
        ※さらに：binutils-2.43でgcc-4.6.4はbuildできないようです。

Appendix C. gcc-9.3.0の場合
    MC680x0用：
        デキマセン

    H8/300用(h8300-hms-elf), SH3用(sh3-hms-elf)：
        CFLAGS="--std=gnu99" configure --prefix=/usr/local --target=h8300-hms-elf \
            --disable-libquadmath --disable-ssp --disable-libssp --enable-languages=c,lto

    ARM用：
	binutils-2.43の--targetはarm-eabi-elfです。
        gcc-9.3.0の--targetはarm-none-eabi-elfです。ゆえに、
        ../configure --prefix=/usr/local --target=arm-none-eabi-elf \
            --with-build-time-tools=/usr/local/arm-eabi-elf/bin (以下同文)
        のようになります。
        ※--exec-prefix=arm-eabi-elfを指定しても、
          "configure: error: expected an absolute directory name for --exec_prefix: arm-eabi-elf"
          と拒否されます。メンドクセエですわね。
        ※なお、newlibはbuildできません。おとなしくti-cgt-gcc-armなどを使いましょう。

Appendix D. gcc-13.2.0の場合
    MC680x0用：
        ../configure --prefix=/usr/local --target=m68k-elf --with-languages="c,c++,lto" --without-fortran \
            --disable-libquadmath --disable-ssp --disable-libssp --disable-shared --disable-shl
        ※with-languagesやwithoutが効かず、gfortranも生成されます。
        ※make installは、libstdc++-v3がエラーとなります。他のgcclibも未検証です。
        ※ちなみに、newlib-4.5のbuildは通ります。
